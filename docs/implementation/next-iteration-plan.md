# Jojo Plan 现状回顾与迭代计划

2026-11-18。源码基线为 `v0.3.1`（`26aa55d`）。本次重新运行类型检查和 27 项核心测试，全部通过。现场项目结论采用最近一次 10 月 27 日的实测记录。

## 产品目标与当前差距

你的目标是让 AI 替身按你认可的方法交付工作。选定任务类型后加载对应技能，在同一个对话里持续看到进展、参与审阅、处理返工，最后拿到可用的 Skill、文档或系统。对系统研发，成品需要走过调研与 PRD、UI/UX、团队交底、分析设计、研发与测试反复修复、产品／市场／技术终审，以及面向目标环境的发布交接。

## 优先级和退出条件

### P0 · 0.4.0 本机日用版，先结清现有 Intelligent UI 项目

1. 复用现有成果和实测记录。设计并实现独立的验收证据入口，把验收项、源码版本／哈希、结果、运行环境、日志和复核人关联起来。引入后置测试证据时，按证据依赖更新对应结论。验收标准变化时才重新核对受影响的要求和前序批准。
2. 保留默认断网单测。设计单独显式启动的真实模型集成验证，限定获准的模型目标、调用次数、超时和用量。用已生成的 POC 完成一次 AC-21。当前证据已有 11 项容器单测、8 项 HTTP 检查、6 条本机真实问答，以及两种浏览器视口和键盘操作。容器内真实问答和应用内终审仍待完成。
3. 补齐原生工作区的运行状态。让正在运行、失败、超时、取消清楚可见，重启后能找到选用模型、上一次运行和待审事项。修复表格显示、审阅定位与模型重名辨识。用现有项目和隔离测试数据覆盖升级、恢复、版本失效、无重复执行以及交接包复现。
4. 通过正常产品入口完成研发审阅，产出可审阅的终审结论。用户能看到每条验收项的证据、缺口和复核结论，终审通过后导出可重跑交接包。安装版用真实状态检查键盘、紧凑窗口和长对话阅读。

**通过门槛**：在打包的本机 App 内接着旧任务继续，无须重做已批准阶段。当前源码版本可核验 AC-21，结构检查和最终审批各自可追溯。按阶段保留失败、重试和终审记录。

### P1 · 先用销售穿行跑完团队流程，再迁移到护照校验

1. 在「审计 → 销售穿行」完成调研、PRD 和验收约定，再出 UI/UX。交底由产品和设计提交基线，架构、开发、测试分别反馈理解与异议。架构产出架构图、ER、数据流、接口和部署说明；测试场景与 PRD 条款逐条绑定。
2. 按已确认的首批材料，用 IPO 披露验证页码与程序提取，再用明确标注的模拟原始单据验证合同／发货／开票／记账／收款之间的证据图。优先做本案确需的批次导入与单据解析，缺件、金额或日期冲突要能回到具体材料及规则版本。审计准则映射和专业结论留有复核状态。
3. 在原型系统中走一次「测试提缺陷 → 开发修复 → 测试独立复测 → 关闭」，再走一次「产品修改规则 → 架构评估影响 → 下游重验」。产品、市场、技术分别形成终审意见。交付可重跑源码、用例、报告及部署／回滚说明；验证后支持对生成系统做本地 Git 提交。用真实运行记录显示角色与 Job。
4. 将同一套需求、证据、规则及复测流程迁移到独立的「护照校验」项目。用公开示例验证可读性、字段与规则命中、证据不足及人工复核。真伪准确率另需可靠标签与相应验证条件。IPO 审计留在审计项目下，待定义自己的任务合同。

**通过门槛**：销售穿行能从一条报告结论回查规则、单据、页码或字段，并在修改规则后定位受影响的用例和报告。至少一次独立复测及一次产品／架构返工实际完成，终审可查到证据。护照能用同一工作区完成独立项目交接。

### P2 · 让 Skill、文档和 PPT 能复用同一套工作方式

1. 实现版本化工作包加载，逐步替换三个写死入口。新建时展示所选流程、必需／可选技能和能力，已存在的工作继续按其锁定版本运行。提供独立的搜索设置，让搜索发现、原文读取、引用与事实核查形成一条可复现流程。
2. 重做一次真实 ontology 任务。交付八个可单独使用的 Skill 和带输入／输出约定、成员版本及依赖的组，保留单 Skill 出口。用一条含糊输入、一个反例和一次成员版本变更验收整组运行。
3. 先跑通小白 CI/CD 经验分享和模型测试报告。分步审阅大纲、正文、依据，首批提供 Markdown 和可编辑 DOCX。测试报告从实际记录引用模型版本、配置与结果。然后把已审阅的 CI/CD 文档作为 PPT 工作包第一例，在同一对话产出故事线、预览、逐页审阅和可编辑 PPTX。

**通过门槛**：加入 PPT 不改工作区全局导航。Ontology 组可复现运行，两个真实文档可独立交接。用两次不同工作检查准则是否正确进入任务、能定位来源、撤回后不再使用。

### P3 · 发布交接与价值验证

生成系统的发布流程优先在本机或授权的测试目标演练候选版本、预检、触发、验证与回滚。具体生产环境接入由项目决定。Jojo 本身继续提供本机安装与恢复，签名公证、Intel 和外部推广排在当前范围之后。

每个真实任务记录人工活跃分钟、重复解释次数、找证据时间、改需求后的漏验与误伤、费用和终审结果。先用销售穿行规则变更及 ontology 二次执行，对比你惯用的模型工具加模板和 Git 的流程，尽量保持材料、模型、权限及验收条件一致。把实测的减少核对与返工时间作为用户演示、市场话术和投资人材料的依据。安装版每轮从实际截图、键盘、状态变化和恢复行为复查设计品质。参见[对照实验方案](../strategy/05-validation-plan.md)。
