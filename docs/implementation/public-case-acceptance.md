# 首批公开领域材料与验收计划

2026-10-10。用户已授权使用网上护照图片与网上公司 IPO 销售穿行案例，发行范围为本机。以下是已核对的首批来源及研发验收设计；**尚未执行图片识别、完成领域系统或通过领域准确率验收**。原 0.2.0 的合成验收记录保持原样，不更名为真实领域验收。

## 项目与工作关系

- 护照校验项目：公开示例材料研究 → 护照页校验 PRD → 识别/规则/风险输出实现与测试。
- 审计项目：销售穿行工作；IPO 审计另建工作，可引用同一披露材料，采用各自验收合同。
- ontology 8 Skill 组属于方法与交付能力，不能替代两个系统各自的专业验收。

## 护照：公开样本与校验能力

首批使用美国国务院的[护照设计与安全特征页面](https://travel.state.gov/en/passports/apply/help/security-design.html)。官方页面提供带人像的示例数据页，可用于建立版式、字段与示例识别用例。另核对了[Commons 对应文件及来源/许可说明](https://commons.wikimedia.org/wiki/File:United_States_Next_Generation_Passport_signature_and_biodata_page.jpg)：页面注明源自美国国务院，并标注美国联邦政府作品的 public-domain 状态。登记具体图片版本、原始链接、取得日期与文件摘要，不只保存搜索缩略图。[来源：美国国务院](https://travel.state.gov/en/passports/apply/help/security-design.html)、[图片来源与许可记录](https://commons.wikimedia.org/wiki/File:United_States_Next_Generation_Passport_signature_and_biodata_page.jpg)。

英国 HM Passport Office 的[基础检查指南](https://www.gov.uk/government/publications/basic-passport-checks)作为检查思路的官方参考。PRADO 可作版本/特征参考链接，但其[专项使用条件](https://www.consilium.europa.eu/en/about-site/copyright/)有专门限制，不默认批量复制其图片；优先上述来源清楚的示例素材。

| 样本分组 | 标签规则 | 首轮能验收什么 |
|---|---|---|
| 官方示例页 | official_specimen；不是实际有效护照，也不是已认证的真实交易凭证 | 数据页定位、人像区域存在、示例标记识别、可读字段与置信度 |
| 低质量/损坏输入 | 明确记录本地测试构造方法，不宣称来自真实欺诈案件 | 无法解码、缺页、低可读性时保留错误原因与人工复核状态 |
| 字段/MRZ 规则用例 | 独立标记 synthetic；预期由规则计算或人工审核建立 | 字段一致性、日期、可解析格式与校验位；规则通过不等于证件真实 |
| 真实欺诈／真实已认证证件 | 当前没有可靠标签集 | 不报告真伪准确率、召回率或可商用鉴假结论 |

建议的初版输出为：来源/版本、识别字段、置信度、规则结果、可疑点、未检查的特征和人工复核建议。客户传一张图片的入口保留，但单张普通图片没有原件触感、透光/紫外或芯片检查证据，不能因此作出“已认证真实”的承诺。PRADO 的[检查说明](https://www.consilium.europa.eu/prado/en/prado-faq/prado-faq.pdf)也区分了这些检查条件。

## 销售穿行：IPO 公开披露案例

首批选择**珠海市杰理科技股份有限公司**《首次公开发行股票并在创业板上市申请文件的第二轮审核问询函的回复》，文件署期 2022 年 5 月，来源为[深交所披露 PDF](https://reportdocs.static.szse.cn/UpFiles/rasinfodisc1/202206/RAS_202206_0001810FF1028E3FC1045F490434003F.pdf)。这是一份 IPO 申请阶段文件，不据此推断该公司最终上市状态。

已定位文件印刷页 1-53／1-54，对应 PDF 第 54／55 页（从 1 开始计页）：含销售收入穿行程序、130 笔抽查说明、客户收入覆盖情况以及截止性核查。用于提取“披露了哪些程序、需要哪些凭证、证据链有哪些节点”，不把中介机构披露的结论直接转成我们系统的实测结论。[来源：深交所原始披露](https://reportdocs.static.szse.cn/UpFiles/rasinfodisc1/202206/RAS_202206_0001810FF1028E3FC1045F490434003F.pdf#page=54)。

首轮交付三类材料：

1. 披露事实索引：公司、文档、版本、页码、核查步骤、材料清单与结论归属；保留原始出处，不编造未披露的逐笔交易。
2. 规则与证据图设计：按合同/订单、发货、签收、发票、记账、回款等节点定义关系、必要字段、金额/日期/主体匹配及缺件状态。具体节点取决于业务和原文材料；不是所有业务都要求同一链条。
3. 独立模拟业务包：以 DEMO-IPO-001 等虚构主体构造用于软件验证的正常、金额差异、主体差异、时点异常、缺件和重复单据；与杰理科技事实索引分开，不冒充该公司的真实单据。

| 验收项 | 预期 | 不能据此宣称 |
|---|---|---|
| 披露解析 | 页码定位准确；程序、材料与结论可追溯；未披露字段显示缺失 | 已取得原始业务凭证 |
| 证据链 | 每条边能定位对应材料/字段；模拟正常链闭合，反例解释差异 | 公开回复里未提供的凭证已被核验 |
| 规则执行 | 相同输入规则结果可复现；缺件输出证据不足，冲突输出具体差异 | 全面符合所有审计标准 |
| 报告 | 区分原文披露、程序实际执行、模拟结果与人工判断 | 公司通过/未通过本系统审计认证 |

审计标准映射另立版本化规则与适用范围，专业判断仍需审阅；首轮材料研究不直接给该公司新的审计意见。后续 Python/PDF/OCR 工作包须能导入原始 PDF/图片并保留页码及解析来源，目前 0.2.0 仍仅支持文本材料与公共静态正文。

## 本机执行顺序与退出条件

1. 登记来源清单与许可/使用条件；后续获取原始素材并记录 SHA-256、版本、解析方式与派生关系。当前本文件完成的是来源核对与计划，不是图片/PDF 下载或解析验收。
2. 分别出两项工作的研究、PRD、UI/UX、架构和测试设计，按已确认阶段门槛推进。
3. 优先实现 Python＋外部能力接口，再实现 ontology Skill 组与独立 BYO 搜索配置；外部模型/搜索不继承本机读取的默认授权。
4. 正常与异常用例均有可审核预期；原始样本、披露事实和模拟数据保持不同标签。没有可靠真伪标签/原始凭证时，明确收敛到可验证的功能范围。
5. 本机导入、执行、重启、返工和交接通过后，记录新的领域功能验收；继续保留 0.2.0 基线历史。本阶段不安排外部发行、云部署或签名采购。
