# MVP 新增待拍板项

2026-10-10。既有 D01–D06 保持不变；本轮已按下列建议默认推进。这些是后续范围选择，不要求先回复才能试用。

| 项目 | 已采用的建议 | 后续需你决定 |
|---|---|---|
| 系统首个可执行技术栈 | 无第三方依赖的 Node.js Web/API，固定 Node 测试 runner；完整团队文档与审批仍保留 | 下一栈优先 Python/OCR/模型 API，还是完整 React/数据库工程？建议跟随销售穿行与护照两个真实项目选 Python＋外部能力契约 |
| 联网调研 | 读取用户指定公共 HTTPS 静态正文并保留来源；自动搜索发现暂不宣称已实现 | 首个搜索供应商及计费/数据范围。建议独立 BYO 搜索配置，查询与材料发送分开授权 |
| 审阅负担 | 系统七阶段均要用户确认，避免模拟团队自动把猜测当验收 | 真实用两轮后，是否把研究/测试设计改为可选自动通过？关键 PRD、UX、架构、终审建议保留人工门槛 |
| Skill 交付粒度 | 单个标准 SKILL.md，可在同项目显式复用冻结版本 | ontology 的 8 Skill 是否首批升级为带数据映射、回归样本的 Skill 组？建议下一轮优先，因为贴近你的真实交付 |
| 第一批真实验收任务 | 合成 API、基于实测日志的文档、需求澄清 Skill 已通过；没有用真实客户资料冒充领域验收 | 你提供哪些脱敏销售穿行/护照材料与期望交付标准，采用哪个模型服务。建议先做文档与 PRD，再接外部识别/解析能力 |
| 对外发行 | 可本机试用的 arm64 开发安装包，未 Apple 签名/公证 | 是否申请开发者签名、确定品牌/数据政策并做干净机验收，再邀请外部试用 |

没有这些选择前，MVP 仍可做材料整理、文本/Skill 交付和受限系统研发；不能把它宣传为已完成客户护照鉴假、IPO 审计认证或自动发布生产系统。不可替代性仍是待验证的业务假设，不能由功能数量或本轮测试直接证明。
