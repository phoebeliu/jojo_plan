## 已确认

- 产品名：jojo plan · 替身计划。
- 面向 AI 工程师，可安装于 Mac。
- 选择职能后加载技能，用户配置模型。
- 三类工作：制作 Skill、写文档、开发系统。
- 开发遵循研究/PRD → UI/UX → 宣讲及系统/测试分析设计 → 开发测试循环 → 最终综合验收。
- 产品和架构问题可在研发中回流研讨；验收不通过继续整改。
- 当前先研究并完善 PRD，不先制作界面原型。
- ontology 真实任务交付了 8 个 Skill，处理模糊输入并产生系列分析输出。
- 已知写作类别是小白 CI/CD 经验分享和模型测试报告。
- 审计系统案例明确要求从零开发到生产发布。

## 调研下一步

1. 用真实案例还原输入、操作、交付、返工与耗时，验证三类工作的共同点和差异。
2. 围绕选定场景深入阅读 BMAD/Spec Kit 的具体交接与纠偏机制，以及候选引擎的恢复/取消接口；固定版本。
3. 补充直接面向用户的同类应用比较，覆盖实际操作路径、成果审阅、模型配置和价格，而不仅是框架能力。当前未完成此项。
4. 用相同案例评估“现有工具加方法包”能否满足需求，确定独立应用的必要性。
5. 形成候选技术验证结果。必要时先作不涉及产品界面的独立实验，明确实验范围，不把它当产品研发启动。
6. 收敛首版范围、非目标、质量标准、成本范围和阶段授权，更新 PRD，再进行产品评审。

## 产品阶段出口

- 核心用户场景有真实案例支撑。
- 直接替代方案、框架能力及限制有来源，关键未知有验证结果或明确处理方式。
- 三类工作各自输入、过程、交付和异常流程明确。
- 首版范围与非目标明确，技术可行性足以支持承诺。
- PRD 关键需求有验收标准，核心决策不再悬空。
- 产品方案评审通过后交给 UI/UX；设计通过后宣讲并进入系统与测试分析设计。

当前结论：已建立首轮资料与需求讨论基线，尚不满足产品阶段出口。
