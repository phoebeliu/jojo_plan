# 用户说明与市场材料

所有文案用于评审，未发布。现阶段 CTA 只能是「查看设计 / 参与试用研究」，不能写「下载即用」。

## 给第一次了解的人

**让每次 AI 交付，都说得清、查得到、接得住。**

老板说「做一个销售穿行系统」，你还要弄清哪些单据能支持哪些结论，设计界面和系统，反复改代码与测试，最后让别人接手。jojo plan 正在设计一种工作方式：先把「怎样才算做好」说清楚，再把研究、文档、代码和检查结果连起来。需求改变时，找出需要重做和重新验证的部分。

你仍在一个对话里工作，也能看智能体和后台任务的进展。需要你判断的不是一堆角色发言，而是缺失的依据、关键取舍和待验收的成果。技能、文章、系统未来都沿用这套方式；制作PPT将作为后续工作包扩展。

目前只有设计与交互演示；尚不能连接模型完成真实交付。AI和检查工具也不能替代需要专业判断的审计、证件鉴定或生产发布责任。

## 用户常见问题

**我已经用 Codex 或 Claude Code，为什么还要 jojo？** 如果你最费时的是在需求变动后核对多份成果、补证据和准备交接，jojo计划帮你减少这些工作；如果你主要修改代码且现有工具够用，没有理由为了更多Agent图标换工具。先在一个真实返工任务上对照，再决定是否采用。

**和 Hermes、DeepSeek Harness 有何关系？** 它们已能组织Agent、工具和自动化。jojo的重点是项目验收与变更记录；这些工具也能通过方法或扩展达到类似目标。我们没有已验证的效率优势，也未完成原生连接器。

**不会配置模型能用吗？** 首版针对AI工程师，需要模型服务和必要工具配置；产品说明让非技术读者理解，不意味着首版面向所有消费者。

**我的资料会被用来改进公共技能吗？** 默认不会。项目资料与记录属于用户；外传处理和未来共享分别获得授权。可导出成果，不以封闭格式绑住用户。

## 90秒演示脚本

0–20秒：展示真实痛点「老板改了缺件规则，哪些成果仍有效？」打开审计项目中的销售穿行工作项。

20–40秒：打开交付约定，看一条要求对应的材料、规则设计与测试证据。屏幕明确标注「合成示例，尚未真实运行」。

40–65秒：预演修改。说明规则设计、接口说明、验证结果需要复核；上一版本检查通过不会自动延续到新要求。应用示例变更后，交付状态阻断。

65–80秒：展示持续对话和 Agent / Job 详情；补充信息回到同一工作项，不再让用户管理14个页面。

80–90秒：展示接手者需要的版本、依据、缺口与下一步。说明当前为设计，邀请参与研究；不播放伪造的真实运行录屏。

## 宣传主张清单

## 推广顺序与素材

先面向AI交付负责人，以「一次需求变更的前后对照」作为内容主题。后续准备去敏案例与失败修复记录；本轮已提供[空白交付约定](delivery-contract-template.md)，而非泛泛的多Agent宣传。后续访谈、社群发布、伙伴联系都需另外授权；本轮不发送任何外部消息。

观察从查看案例→愿意提供匿名任务→完成一次试用→第二次主动使用的转化；不把点赞、访问量或候补名单当付费需求。投资人材料使用[商业备忘录](03-business-and-moat.md)，不把用户文案当已验证商业结论。
