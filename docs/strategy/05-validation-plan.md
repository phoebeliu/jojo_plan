# 如何证明值得用，以及何时放弃

本文件是未执行的实验方案；没有用户访谈记录、对照分数或付费数据。阈值为建议，不能反写成结果。

## V1：痛点定位

招募5–8位近期独立负责AI项目交付的用户，至少包含不同现有工具习惯。问最近一次需求变更的实际文件、时间线、返工动作和交接问题；不要先推销产品。让其自记一周：研究、实现、证据整理、解释/协调、排查不一致各花多少时间。只有至少一半用户把跨成果核对/返工列为前两项成本，才继续当前切口。若主要时间在算法效果/OCR，优先考虑领域能力，而非强化流程管理。

## V2：对照任务

使用合成或经授权脱敏材料，四类任务：销售穿行系统规则变更；护照校验系统支持范围变更；Ontology技能组输入变化；模型报告数据更正。PPT作为后续迁移测试，不假定已实现生成。

| 条件 | 做法 |
| --- | --- |
| A 最佳现有流程 | 参与者熟悉的Codex/Claude/Hermes/DSH，加BMAD/Spec Kit或自选方法；允许合理配置和同等学习时间 |
| B jojo闭环 | 同样任务、材料、验收条件和预算；尽可能同模型版本和工具权限 |
| C 轻量替代 | 相同交付模板、检查脚本和Git记录，放在现有工具内，不用独立jojo桌面 |

至少12个独立任务实例，分4类，每类3个；同一实例的等难度变体随机交叉分配，避免先做过答案泄漏。记录模型/版本/提示/权限/工具、方法版本、人工干预、初始配置与运行成本。不能同模型时明确分层，不能把模型优势归因给jojo。评审者尽可能不知道工具条件，以预登记的标准评审完整成果。

每例预埋一个会让旧证据失效的变更、一个缺依据的声明及一个无关成果。衡量：是否漏掉受影响项，是否误伤无关项，是否错误宣布通过，是否能查清版本和依据。

## 指标与建议继续门槛

- 主指标：从收到变更到交付可验收版本的**人工活跃分钟**（含配置、整理、误报修正），报告中位数、逐例差值和范围；不得用Agent运行时长替代。
- 质量约束：严重误交付为0；已知受影响项检出率≥90%，误报率≤20%；这只是小样本门槛，不证明现实中绝无遗漏。
- 收益假设：相对A人工时间中位数减少≥30%，且盲评质量不降低、总工具成本增加≤20%。跨模型结果单列，不混合得出效果宣称。
- 形态选择：若C达到B收益的90%且上手更轻，优先做插件/方法包；不要继续为独立桌面界面扩张成本。
- 关系维护：若人工修关系消耗超过节省时间，减少强制关系范围或停止该功能。
- 不完整/中断任务计入失败分母，保留原因，不能只挑成功案例。样本小先看可行性，正式宣传需扩大样本、报告不确定性和复现材料。

## V3：复用和付费

连续观察两次真实交付周期：是否至少3/5参与者无需催促再次使用；是否愿意为实际价值付费；是否能独立导出并继续工作。研究补贴和付款意愿分开。没有用户允许，不采集客户原件，不自动联系老板/客户。

付费意愿不是收入。只有明确试用范围、产品可用性和收款授权后才能开展付费试点。拒绝记录和流失原因与积极反馈同样保留。

## 记录模板

每次记录：experimentId / participant匿名ID /任务类别/条件/顺序/模型与工具版本/输入hash/验收标准版本/人工分钟/运行分钟/成本及未知项/遗漏数/误报数/严重错误/盲评/是否中断/原始记录路径/授权范围。缺字段显示unknown，不补造数字。

## 停止与转向

两轮迭代仍未达到痛点或收益门槛：停止宣传「交付工作台优势」，选择更轻的插件形态或重新研究领域切口。达到门槛后也只能说在该任务、配置和样本中有效；不能升级成「独一无二、不可替代」。竞品每次重大更新后重跑固定留出任务，结果可能推翻原结论。
