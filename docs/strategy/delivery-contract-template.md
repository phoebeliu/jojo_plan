# 交付约定（空白模板）

用途：在开始执行前，把结果与检查方式说清楚。可以复制到现有AI工具使用；不需要安装jojo。短任务先填1–3条，系统研发再逐步细化。填写不等于已通过验收。

- 项目 / 工作项：
- 请求人 / 最终验收人：
- 本次目标与使用者：
- 需要交付的文件、系统或技能：
- 不包括的范围：
- 输入材料及版本 / 可发送给模型的范围：
- 尚未确认的前提：
- 本次约定版本：

| 编号 | 什么结果才算满足 | 用什么方法检查 | 预期或阈值及适用范围 | 是否必须满足 | 当前依据版本与定位 | 缺口 |

## 需求变更时

- 哪条要求从什么变成什么：
- 原约定版本 / 新草稿版本：
- 已知受影响的设计、实现、文档、测试：
- 关系覆盖尚未确认的部分：
- 无关且保持有效的成果及理由：
- 需要重跑或重审的项目：
- 旧证据保留位置 / 不再适用的原因：

## 交接时

- 最终候选版本及文件清单：
- 每条要求的当前检查结果与可信依据：
- 人工审阅人、时间、对象版本与决定：
- 未解决问题、已接受例外及其理由：
- 被排除的受限材料及获取方式：
- 接手人如何复现 / 下一步：

不要把“Agent说完成了”写成已运行测试。新版本不能直接复制旧版本的通过结论。专业判断的适用范围、依据和负责人必须清楚。
