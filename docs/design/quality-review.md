# Design Edition 02 · 品质标准与迭代记录

2026-10-02｜产品基线 JP-1.1。用户要求以 Awwwards、Webby Awards、FWA 获奖作品的品质为目标，自检并反复改进。本轮范围是交互设计交付；没有开始真实桌面应用或 Agent 后端研发。

## 1. 参考标准与适用方式

- **Awwwards**：官方作品评分页列出设计40%、可用性30%、创意20%、内容10%。用于提醒本项目同时审查视觉、操作与内容，不把截图外观当全部质量。[官方作品评分示例](https://www.awwwards.com/sites/redsofa)
- **Webby Awards**：Apps, Software & Immersive标准涵盖内容、结构导航、视觉、功能、交互、执行、创新和整体体验等维度。本产品主要参考应用/软件维度。[官方评审标准](https://www.webbyawards.com/judging-criteria/)
- **FWA**：官方周年说明强调数字体验的创意、原创性与技术完成度。本项目将“人—替身协作”的识别和交互一致性作为原创方向，不自行编造官方评分权重。[官方说明](https://thefwa.com/FWA25/25.html)

查阅日期为2026-10-02。Awwwards通用evaluation页本次读取超时，因此引用能够读取的官方作品评分页；不宣称该示例就是当前所有类别的统一规则。以上是参考，不代表获奖、入围或得到任何机构认证。我们不以自打9分来证明品质。

## 2. 设计命题

**与另一个自己，共同完成一件工作。** 两个错位而相连的轮廓构成jojo标识；同一图形用于侧栏品牌和主协调Agent头像。暖白纸面支持长时间阅读，紫色表达当前选择和协调关系，绿色只用于明确状态。工作内容是视觉中心，不引入无关3D背景、音效或持续运动。

三个必须一眼回答的问题：现在在哪个项目？谁正在做什么？当前产物在哪里？项目归属保持用户确认的层级：审计项目包含销售穿行/IPO审计，护照校验是同级独立项目。

## 4. 当前设计门槛

| 项目 | 本轮门槛 | 结果与范围 |
| --- | --- | --- |
| 视觉体系 | 品牌、选中状态、字体、图标、色彩与间距一致；无无关装饰 | 已重构并逐张检查桌面、详情、新工作、窄窗截图；视觉判断为设计自检 |
| 核心操作 | 搜索、新工作演示草稿、角色详情、定向补充、暂停/恢复、成果阅读有明确反馈 | 自动浏览器检查；全部行为仅在演示内存中发生 |
| 状态真实 | 不把演示数据标为真实模型、真实进程或正式批准 | 常驻演示标记；新草稿不启动任务；PPT保持规划/不可启动 |
| 阅读连续性 | 工作切换不丢输入/对话/定向对象，初次打开能看最新工作 | 浏览器验证；刷新页面按明确说明重置，不承诺生产持久化 |
| 执行可见性 | 当前工作的Agent/Job分别计数，暂停时同步；排队任务不算活跃 | 演示状态检查；真实运行状态依赖后续服务实现 |
| 适应布局 | 1440×900、1100×720无横向溢出；768×900、390×844兼容阅读 | 逐任务/详情检查；390宽是健壮性检查，不扩张首版macOS定位 |
| 键盘与动效 | 搜索快捷键、面板Tab边界、Esc关闭和焦点返回；减少动态效果 | 浏览器验证；没有后台持续动画或外部动画库 |
| 文字对比 | 普通文字4.5:1、大字3:1为内部检查门槛 | 可见纯色背景文字抽样通过；不等同完整WCAG合规认证 |
| 放大阅读 | 放大文字后内容仍可滚动、页面不横向溢出 | 模拟200%文字放大；不是系统级放大或完整辅助技术验收 |
| 依赖与性能 | 初始界面不依赖网络字体/远程脚本；无脚本错误 | 本地浏览器无外部HTTP请求；未测Electron启动或真实模型延迟 |

最终机器结果：[交互检查](checks/browser-results.json)、[对比度抽样](checks/contrast-results.json)。以其中的实际项数为准；每项组检查包含多个情境，不把其数量当奖项分数。

## 5. 开发必须继承的细节

- 稳定身份：状态投影更新不能令键盘焦点丢失；关闭后回到触发入口。
- 同一状态源：顶部计数、Agent卡、Job列表、暂停按钮读取同一服务快照。
- 选择与输入：输入法组合时不发送；空白不提交；补充按任务保存；切换工作不触发取消。
- 日志与内容：正文以安全文本/Markdown渲染；日志不执行HTML；敏感内容脱敏后再展示。
- 运动克制：只用180–250ms的状态/面板过渡；遵循prefers-reduced-motion，不用无尽动画暗示虚假的工作。
- 可观察的结果：工作卡通向成果、工具记录和依据；未来PPT工作包复用同一交互，不能新增独立导航体系。

## 6. 仍不能由设计稿证明的质量

真正的模型与工具可靠性、长时间后台执行、恢复一致性、安装升级、真实大数据量、屏幕阅读器完整流程、跨浏览器/实际Electron与macOS辅助功能、实际用户任务完成率，以及评委对原创性/影响力的评价，都还需真实应用和外部评审。

因此当前结论是“完成多轮自检的高完成度交互设计交付”，不是“已经达到必然获奖”。获奖品质继续作为后续研发和验收的目标；不以本轮检查替代用户验证或奖项评审。
