# Design Edition 03：可验收交付的工作区

2026-10-08｜定位 S1 / 开发规格 JP-1.1。交付为静态交互设计；演示状态不代表实际Agent、项目验收或获奖结果。

## 设计判断

以「从约定到依据，一条连续的工作主线」组织体验。暖白让长时间阅读舒适，紫色表示当前工作与可操作关联，绿色表示保留的依据，琥珀表示需处理的缺口。相连的轮廓从品牌标识延续到交付摘要；原创表达与实际功能相连。

主工作区回答：离交付缺什么、当前在做什么、接下来需判断什么。交付摘要常驻，执行栏分别列出Agent和后台Job；主区域继续是对话，不把品质管理做成另一套业务导航。

## 相对上一版的修复

| 问题 | 修改 | 设计理由 |
| --- | --- | --- |
| 交付约定埋在对话下方 | 工作标题下常驻交付状态、缺口与约定入口 | 滚动聊天仍能看清结果状态 |
| 新定位只增加一张卡，其他入口仍强调组织Agent | 新工作、能力库、工作说明一起修订 | 让进入产品时就理解可验收交付 |
| 文件数和角色卡压过当前决定 | 缩短阶段摘要、收紧协作卡；完整流程按需阅读 | 留空间给成果与下一步 |
| 依据链只能读，无法验证指向什么 | 关联可点开样本定位、目标版本及示例记录 | 要求、文件、结果真正连起来 |
| 变更前后需要从一段话中寻找 | 原约定与拟议约定对照，列出修订/重验/保持有效 | 让影响范围和下一步可扫描 |
| 交接价值只在策略里 | 同一详情区预览五类交接内容与开放问题 | 展示接手者如何继续，而非仅展示生成文件 |
| 窄窗口详情仅阻止聊天交互 | 同时阻止背景导航、标题和交付入口；关闭恢复入口焦点 | 模态行为与无障碍语义一致 |
| 细节页只能关闭 | 依据、影响和交接页可返回约定；支持宽幅阅读 | 避免阅读一层后丢失工作上下文 |

## 本轮实际自检与迭代

1. 定位审查：发现摘要被埋、入口文案未同步；修订常驻状态与全部工作类型入口。
2. 页面审查：查看1440宽实际截图，发现阶段/协作空间仍过多；将阶段轨道收到完整计划，缩短卡片和预演标题间距。
3. 交互审查：新增依据定位、交接清单、返回路径及摘要滚动可见检查。首轮检查遇到新旧入口的选择器歧义，改为明确定位详情内操作后复验。
4. 可读性/适配审查：复查四种宽度、文字放大、减少动态效果、焦点和文字对比度；最终结果以checks目录的报告为准。

这些轮次由同一代理完成，不冒充独立专家或真实用户评审。自检不使用自行打出的“获奖分数”。

参考 [Webby应用/软件标准](https://www.webbyawards.com/judging-criteria/) 的内容、结构导航、视觉、功能、交互、执行与整体体验；将它们转成能观察的任务路径和状态检查。[FWA周年官方说明](https://thefwa.com/FWA25/25.html)强调创意、原创与技术完成度，本轮将品牌图形与可操作的依据链联系起来，不增加无关效果。Awwwards视觉与可用性方向沿用[前版品质研究](quality-review.md)；本轮官方评分页面读取超时，没有宣称完成新的评分规则核验。

这些奖项各自有不同评审与类别，本地桌面交互设计不等于已有可参赛成品。实际模型工作质量、完整无障碍评估、macOS安装体验、用户采用和外部评审仍需后续实施和证据。

## 演示操作

进入销售穿行工作 → 顶部「查看约定」→ 点E-02查看具体依据 → 返回 → 预演修改 → 查看三项影响与独立格式检查 → 应用合成变更 → 看见旧依据失效与交付阻断 → 查看交接清单。

审计项目与护照项目仍是同级，销售穿行/IPO在审计项目内。Skill、文档、系统继续共用工作区；PPT保留不可运行的扩展示例。未新增全局tab，没有原生连接器或真实导出能力承诺。

## 接给开发团队的状态约束

常驻摘要从服务中当前版本的约定、检查、审批和失效记录推导，不由模型自由编写。修改后需重验与执行暂停独立：暂停Agent不能撤销变更或恢复旧依据。详情返回不创建新任务；导出保留未完成项与受限材料缺口。依据来源明确区分合成、导入与真实runner记录。

本版细化UI-02/03/01/04的表现，仍复用52个RPC方法和既有领域状态。交付约束以[内容规格](../spec/16-delivery-contract.md)为准；演示中的SAMPLE-007及所有状态仅用于验证界面行为。
