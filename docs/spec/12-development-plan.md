# 研发计划、工作包与追踪矩阵

JP-1.0。可开工的是下列实现与验证任务，不是直接发布到客户生产。本轮不创建应用代码。

## 1. 里程碑

| 阶段 | 出口 | 必须先完成 |
| --- | --- | --- |
| P0 基础验证与工程骨架 | 选定依赖锁定；能启动桌面、存取DB、取消fake/Pi任务、启动受控容器 | 阅读交底包 |
| P1 核心工作台 | 三种工作可建、版本/基线/决策/恢复以fake runtime完整运行 | P0 |
| P2 技能与文档真实闭环 | 真模型、来源、技能组和多格式文档通过代表性样例 | P1及真实服务配置 |
| P3 研发协作闭环 | 工程设计、工作树/容器实现、独立测试、缺陷与变更可运行 | P1/P2 |
| P4 综合验收与发布适配 | 候选绑定、授权、幂等pipeline和生产验证在受控环境演练 | P3 |
| P5 分发与交付 | 全部P0/P1用例、签名安装、升级恢复和文档通过 | P4 |

不提供未经团队估算的日历承诺。各工作包完成一次技术拆解后由团队估算；真实模型供应、签名凭据和生产平台是外部依赖，不通过加班假设消除。

## 4. 工作包交付格式

每个工作包：需求ID、实现差异、迁移/接口变更、检查命令及结果、失败/未执行项、截图（适用时）、限制、下一负责人。检查通过后本地提交。契约改变先修改规格并补消费者测试，禁止前后端各自解释字段。
