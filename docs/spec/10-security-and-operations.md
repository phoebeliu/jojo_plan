# 安全、运行、备份与发布设计

JP-1.0。目标是让本地工具可控运行；不声明任何模型或容器能绝对防止恶意输入。

## 1. 信任边界及权限

可信：安装包代码、main、domain service、签名模板。非可信：网页/文档/图片、用户导入技能脚本、模型输出、项目依赖、生成HTML。外部材料中的命令不能修改全局角色、权限或预算。

Renderer 开启 contextIsolation 与 sandbox，关闭 nodeIntegration，禁用任意导航/弹窗，CSP 默认本地资源；generated HTML 在另一个无权限、无 preload 的 sandboxed 视图中，禁止访问内部文件协议和凭据。外部链接默认交系统浏览器，允许http/https，不允许javascript/file scheme。

Main 只暴露列入契约的函数，校验 sender frame、参数大小和 project scope。禁止将 ipcRenderer 作为通用对象暴露。secretToken、fileToken 为一次性、绑定当前窗口/用途/过期时间的不可猜测令牌；服务消费令牌，不相信模型提供的绝对路径。

## 2. 凭据与网络

使用 Electron safeStorage 对凭据加密后保存，macOS 具体安全存储行为按官方文档验证。加密不可用时不持久化明文，提示仅本次会话或修复环境；不在 Git、导出、事件、prompt、命令行参数或截图中输出密钥。

Base URL 必须显式由用户配置。云端只支持HTTPS；localhost的HTTP用于用户配置的本地模型。搜索抓取阻止 loopback、link-local、私网和 metadata endpoints，重定向每跳重新校验解析目标以避免 SSRF；本地模型访问通过独立服务配置例外，不复用网页抓取入口。

每次模型调用校验材料敏感级别和 grant；不默认发送整目录。上传护照、客户资料等需明确选择目的服务与范围。授权撤销阻止新请求；已发给外部服务的内容不能靠本地撤销收回，记录已发生传输。

## 3. 文件与命令

路径以工作区 realpath 为边界，拒绝 ..、路径穿越、软链接越界和导出ZIP危险条目；限制解压文件数10,000、解压总量1GB，超限停止并清理临时区。导入不执行文件宏或脚本。

exec.run 只接受 argv 数组，若必须 shell 脚本则以审阅版本文件在容器执行，不插值用户文本。容器非root、无privileged、无host PID/network、无Docker socket挂载；默认无网络、2CPU/4GB、pids256、单命令超时300秒，可在授权配置内调至1800秒。依赖下载用专门网络阶段与代理策略，随后测试阶段断网。

模型 Worker不获得通用宿主 shell 工具。主机 broker 只执行固定容器/Git/文件操作；项目脚本、包安装钩子与测试代码均在容器中。Pi 不能旁路这些工具绑定。缺容器不静默降级。

## 4. 运行与用量

每个操作有 started/finished/uncertain 与摘要；流式文本可限速展示，状态事件必须持久化。日志记录 correlationId、project/work/task/attemptId、耗时、错误码与脱敏摘要，不默认记录原始prompt和完整文件。

项目用量总和包含失败重试；模型与搜索/OCR各记服务用量。仅模型token可用时其他成本显示未统计。价格来自用户配置并注明日期，估算不等于账单。unknown usage 暂停付费调度，用户可接受保守结算后继续。

service 心跳丢失→UI显示连接恢复→重启服务→数据库核对未完成意图；不把长时间没有token输出直接当失败。首字超时60秒、请求无进展120秒（可配置），超时后取消/核对；外部服务最终状态不确定时保留记录。

## 5. 本应用发布流程

锁定依赖与第三方许可证清单→单元/集成/界面/故障测试→构建arm64 app/DMG→签名公证→干净机安装/升级/卸载验证→版本说明与SHA256→小范围分发。没有开发者签名凭据时可产出内部测试包，但不能宣称满足正式分发验收。

应用更新默认手动检查和安装；有运行任务先暂停并备份，迁移成功才启动新调度。更新失败保留旧包和备份；不让旧版本读取更高schema，必要时恢复匹配备份。初版无需构建更新服务器，可用用户下载签名包覆盖升级。

来源：[Electron 安全](https://www.electronjs.org/docs/latest/tutorial/security)、[safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)、[Tauri 的 macOS 分发说明](https://v2.tauri.app/distribute/sign/macos/)作为签名/公证研究参考；具体 Electron 打包配置在P0验证。

## 6. 用户项目生产发布

候选包含代码commit、构建包hash、工程/验收基线、配置需求、迁移计划、预检结果、smoke定义、回滚目标。任何摘要变化使授权失效。pipeline触发只接受配置的域名及声明式载荷映射；密钥只交给发布适配，不进入Agent上下文。

流程：preflight有效→用户授权（30分钟）→事务消费令牌→外部幂等触发→轮询→生产smoke→交付。授权使用后不得再次触发；响应丢失先查询，无法确认显示uncertain。回滚是另一次明确操作，不能假定数据库迁移总可逆；不可逆迁移须预先说明备份与恢复路径。

首版为通用pipeline适配，不承诺自动创建云账户、域名或基础设施。缺发布平台时保留发布包及待配置状态。

## 7. 备份与故障处理

| 故障 | 行为 | 数据要求 |
| --- | --- | --- |
| 磁盘满 | 停新写入，提示腾空间；保留失败operation | 不生成缺对象的有效版本 |
| DB损坏 | 停调度，提供恢复入口；不自动重建覆盖 | 原文件隔离保留，用户选备份 |
| 模型断网/限流 | 有界重试；展示原因 | 失败也记用量，不丢产物 |
| 容器崩溃 | 保存日志及工作树，标本次失败 | 不自动丢弃用户改动 |
| 服务崩溃 | 重启核对lease与意图 | 不重复执行未知外部操作 |
| 版本冲突 | 拒绝覆盖，显示diff | 保留双方草稿 |
| pipeline未知 | 查询或人工核对 | 不自动重复发布 |

备份包包含DB一致快照与引用对象manifest，但不包含密钥。恢复先校验checksum、schema支持、路径和空间，再导入临时目录，完成后原子切换；旧目录保留到成功确认。恢复不自动恢复旧生产授权或撤销状态，应使未消费授权失效。

## 8. 交付包清单

manifest.json（版本、hash、依赖、来源限制）、PRD/UX/工程与测试文档、代码归档或仓库引用、验证证据、运行配置模板（无密钥）、安装/发布/回滚说明、未解决事项与接受记录。README明确哪些为模拟数据、未实测能力及部署前条件。
