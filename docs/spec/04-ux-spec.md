# UI/UX 设计规格

JP-1.0｜依据 [PRD](03-prd.md)。配套 [界面板](../design/screenboard.html)是可翻阅的静态设计稿，数据均为示例，无模型调用或真实提交。

静态预览：[项目概览](../design/project-overview.png)、[成果审阅](../design/artifact-review.png)。界面板左侧为设计页面索引，供审阅全部页面，不是最终产品导航；实际产品导航按下一节实现。

## 1. 交互原则与信息架构

用户首先看到工作目标、成果和待处理事项。角色消息作为活动记录，不占据主页面；默认不展示内部提示、完整工具参数或模型推理链。用户可展开执行日志以定位失败。

全局导航：工作台、项目、技能库、待我处理、设置。项目导航：概览、材料、成果、团队任务、验证、发布。项目下新建工作项时选择“制作 Skill / 写文档 / 开发系统”。同一项目可同时有多类工作，状态各自独立。

布局：1440×900 参考画布；最小 1100×720；左导航 208px，顶部 64px，主内容边距 28px；需要证据/评论时右侧 320px 可折叠。窄窗口先收起右栏，保留主操作，不缩小正文到难读。侧栏与主区独立滚动，顶部状态常驻。

视觉：暖白背景 #F6F5F1、白色卡片、深灰正文 #202521、森林绿主按钮 #235A45、琥珀待处理 #8A5900、红色错误 #AD3434；系统中文字体，正文 14px/22px，小字至少 12px，标题 24–28px；间距 4/8/12/16/24/32，圆角 8/12。所有状态有文字与图标，不能仅靠颜色。暗色模式后续，首版不承诺。

## 2. 页面清单与行为

| ID | 页面 | 主要内容与操作 | 空/失败/等待状态 |
| --- | --- | --- | --- |
| UI-01 | 初次设置 | 项目目录、模型连接入口、使用说明；可先进入离线工作台 | 未配置模型时生成按钮提示去设置，仍可编辑文档 |
| UI-02 | 工作台 | 三个职能卡片、最近工作、待处理计数；新建项目 | 首次显示示例输入提示，不创建假项目 |
| UI-03 | 新建工作 | 项目、名称、职能、目标、材料、交付格式、模式、预算、技能摘要 | 必填为空就地提示；缺能力可保存草稿，不能运行对应步骤 |
| UI-04 | 项目概览 | 阶段条、当前成果、执行任务、阻塞原因、用量；暂停/继续/取消 | 恢复时显示“正在核对上次操作”；缺环境显示明确修复入口 |
| UI-05 | 材料与来源 | 文件分类、解析进度、来源URL/时间、引用位置、发送模型许可 | 部分失败逐文件重试，不让整批消失；重复内容提示复用 |
| UI-06 | 成果审阅 | 正文、版本、差异、引用与评审意见；批准/要求修改/导出 | 旧版批准按钮禁用并说明新版本；保存冲突提供对比，不覆盖 |
| UI-07 | 待我处理 | 按影响排序的决策、审批和授权；建议方案、备选、影响范围 | 没有待办时显示下一工作；超时不默认同意；已处理保留历史 |
| UI-08 | 团队与任务 | 角色、任务、依赖、输入版本、成果、阻塞；指派或重试 | 不以“角色在线”表示任务完成；失败显示原因与重试影响 |
| UI-09 | 变更影响 | 原/新版本、变更摘要、受影响成果任务和评测；提交变更 | 分析未完成可保存草稿，不自动应用；冲突需要选择有效版本 |
| UI-10 | 验证中心 | 软件测试、业务评测分组；版本、样本、失败、缺陷与复测 | 未执行显示未执行；合成结果标示模拟；不可用指标不填零 |
| UI-11 | 技能库/技能组 | 名称、说明、版本、验证状态、依赖图；导入/复制/验证/启用/导出 | 未验证可编辑不可启用；缺依赖或循环显示节点定位 |
| UI-12 | 发布与交付 | 候选、预检、目标、授权、pipeline状态、生产验证和回滚 | 无目标显示待配置；触发超时显示结果待核实，不鼓励重复点击 |
| UI-13 | 模型与工具设置 | 协议/URL/型号/凭据、能力检测、角色配置、搜索/OCR/执行环境 | 401/限流/超时/不支持能力分开；已存密钥只显示是否存在 |
| UI-14 | 数据与项目设置 | 权限、备份/恢复、归档、删除、用量限制、Git 策略 | 数据迁移/备份失败保留原状态；删除明确仅应用副本 |

## 3. 关键页面细节

### UI-03 新建工作

名称 1–80 字；目标 1–20,000 字；必须选项目和职能；材料可选。默认“关键点确认”，另有“先推演：缺失信息采用假设继续出草案”。预算输入为正整数，默认 200,000 tokens，必须确认才开始真实调用。模型密钥不在此页重复输入。

第二步显示将采用的角色、技能版本、材料发送范围和缺少能力。单一主按钮“开始工作”；保存草稿为次按钮。开始提交 requestId，成功返回工作页；超时查询同 requestId，不重复创建。

### UI-04 概览

阶段条可显示六组：研究/PRD、UI/UX、宣讲、工程设计、研发测试、验收/发布；组内仍显示当前真实stage_key对应的子阶段和门槛。六组展示不合并后端的八个研发阶段。

顶部“销售穿行系统 · 工程设计中”，并展示真实阶段，而不是统一“思考中”。主卡片显示最近成果与下一出口条件，右侧只列待决策事项。任务列表显示正在做什么及可验证成果；用量显示已用/预留/上限。

暂停：立即显示“正在暂停，已发出的操作可能仍在结束”；只有 service 确认才显示已暂停。取消：二次确认仅因为会终止本工作后续任务，说明保留已生成成果；对在途发布另列外部状态。

### UI-06 审阅

顶部固定版本、状态、输入基线与作者角色；中间 Markdown/图表/PDF预览，切换“正文 / 与上一版比较”；右栏意见可绑定段落或全局。底部主操作“通过此版本”，次操作“要求修改”。要求修改必须填写原因；通过请求携带 baseline hash，服务判定已过期则显示“依据已变化，请查看新版本”。

用户直接编辑正文先生成 draft；保存后的文案“草稿已保存，尚未替代当前基线”。提交新版本时显示影响预览。审阅记录不能被作者直接删改。

### UI-07 决策

每项固定呈现问题、推荐选择与理由、选项代价、受影响阶段、谁提出、需要何种批准。普通产品决策可采用建议；生产授权有独立卡片，明确环境、提交版本/包摘要、迁移及回滚计划，不能与其他项批量通过。

“按建议继续推演”生成 assumed 记录；不会显示用户头像或“你已批准”。需要真人领域确认时显示缺失证据，不能通过默认推荐隐藏。

### UI-10 验证

软件测试/模型效果/技能验证三类标签；每条结果显示实际运行或模拟、测试定义版本、受测代码/模型/规则/样本版本与执行时间。失败转缺陷，已有同指纹缺陷则追加复现证据。开发修复后为“待复测”，仅有新的测试通过证据才可关闭。

### UI-12 发布

步骤：目标配置 → 发布候选 → 预检 → 待授权 → 发布中 → 生产验证 → 已交付。显示明确包摘要、外部 run 链接和未完成项。发布按钮只在预检有效且候选未变时可用；点击后进入专用确认，展示风险/恢复方案和目标，不依赖一句聊天“好”。

外部成功不等于产品交付，须记录 smoke checks；失败显示“查看执行记录 / 按已批准方案回滚”，新目标或新版本必须重新授权。离开页面不取消发布。

## 4. 全局状态与文案

| 状态 | 用户文案 | 可用操作 |
| --- | --- | --- |
| queued | 等待执行 | 暂停、取消 |
| running | 正在处理：任务名称 | 暂停、查看成果 |
| waiting_input | 需要补充信息 | 打开问题、采用假设（适用时） |
| waiting_approval | 等待审阅 | 查看材料、通过/要求修改 |
| paused | 已暂停，成果已保存 | 继续、取消 |
| reconciling | 正在核对上次操作 | 查看记录；不显示盲目重试 |
| blocked | 暂时无法继续：具体原因 | 配置、修订或重试 |
| failed | 本次执行失败，已保留成果 | 查看原因、创建新尝试 |
| delivered | 已交付：版本 | 查看清单、导出 |

## 5. 键盘与可访问性

Cmd+N 新建工作、Cmd+K 搜索/导航、Cmd+S 保存草稿、Esc 关闭非破坏性弹层。禁止快捷键直接批准生产。Tab 顺序按阅读顺序，弹层陷入焦点，关闭后回原触发点；按钮有可读名称；输入错误关联字段；动态图每个节点提供等价列表。正文缩放 200% 可阅读；表格可横向滚动不截断关键操作。

## 6. 设计交付与前端验收

界面板覆盖核心页面结构，本文补齐全部 14 页和状态。实现以页面 ID 和接口契约对应；展示数据不得直接改 service 状态。组件集包括 StageStepper、ArtifactCard、VersionDiff、EvidenceLink、DecisionCard、TaskTable、UsageMeter、CapabilityBadge、IssuePanel、ReleaseStepper。

UI 验收：正常/空/加载/错误/权限不足/过期/离线/恢复八类状态有设计；能从工作台到成果、从结论到证据、从变更到失效测试；模型调用不阻塞页面交互。图中的示例数字及“已通过”均为设计数据，不作为真实成果。
