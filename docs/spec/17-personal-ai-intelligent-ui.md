# S2 Personal AI与Intelligent UI补充规格

2026-10-09｜JP-1.1的后续扩展设计，待实现；本轮只改静态设计。原45张表/52命令不自动获得下列能力。S2落地前须版本化扩展契约与迁移，不能将旧规格检查通过算作记忆系统已实现。

## PA-01：工作准则与来源

每条准则具有id、revision、kind（preference/project_rule/method）、scope（personal/project/work）、scopeId、statement、status（proposed/confirmed/disabled/superseded/forgotten）、sourceRefs、createdAt、expiresAt、sensitivity与确认记录。sourceRefs引用消息/决策/产物版本，不能只记录模型自述。个人scope不含客户原件或业务规则。

首版只从用户导入或明确接受的工作记录产生候选；不持续读取屏幕、邮箱、全部文件或生活历史。模型推断为proposed，用户确认后成为confirmed。UI中的已确认准则为本对话中用户明示习惯的演示副本，不表示应用真的写入了长期存储。

## PA-02：使用与冲突

服务在每次任务边界选取适用准则，记录版本、使用原因与目标任务。当前明确要求优先于适用的项目规则与个人偏好；涉及真正业务规则修改仍走变更预演，不能只覆盖文字。权限、预算、生产授权、必需验收条件永远不被个人偏好放宽。

审计的规则只对审计项目适用；护照项目可以复用研发方法，不能复用审计容差。过期、禁用、遗忘、未确认项不注入新模型调用。跨scope推荐先解释和取得选择，不能靠embedding相似度绕过项目隔离。

## PA-03：方法学习

复盘产生method候选，关联失败、修复、适用前提、验证样例、反例及对应产物版本。用户接受仅代表允许进入验证；回归检查/内容审阅完成后才成为可启用方法或Skill版本。点赞、通过一次样例、模型总结都不等于方法已校准。启用不改写正在运行中锁定的Skill。

## PA-04：用户控制和撤回

查看来源、纠正为新revision、禁用、忘记与导出必须可操作。忘记会移除可用正文、索引、待派发上下文与候选副本，保留最小无正文撤回审计。不能声称撤回已发送给外部模型的历史上下文；在新的安全边界重建会话、停止后续使用。备份恢复要应用遗忘墓碑，否则可能重新导入已忘记资料；仅从用户明确选择的导入恢复。

全局关闭与工作项临时关闭分开；临时关闭个人准则不删除数据、不停Agent、不改变项目验收状态。所有按钮说明影响范围。

## UI-INT-01：受控情境组件

ViewIntent为声明式数据：schemaVersion、workId、targetFingerprint、componentId、reasonRefs、memoryRevisionRefs、priority、expiresAt、payloadRef、suggestedActionIds。componentId只允许证据核查、范围澄清、方法验证、来源核查、变更复核、交接清单六类。payload从可信对象读取，不允许任意HTML/JS、远端URL或任意命令字符串。

客户端验证组件目录、工作scope、对象版本、权限、枚举和大小；非法提案拒绝，回退稳定对话与交付摘要。生产发布、权限与版本审批控件固定，不可被生成视图替换。建议与真实操作分开，每个行动仍执行领域服务检查。

## UI-INT-02：何时适配

场景、阶段与明确事件决定候选：缺范围→澄清；缺原始记录→核查来源；方法候选→验证；上游改变→变更复核；候选交付→交接检查。用户明确要求和新版本的阻断问题优先，其次个人偏好。低置信度保持默认组件并解释未知，不显示虚假准确率。

输入中、选中文字、详情阅读或审批期间不自动改变布局；将待推荐更新放到提示中，由用户接受或安全边界再呈现。稳定区域始终是导航、主对话、交付摘要和执行观察。刷新不随机改变组件。

## UI-INT-03：解释、固定与反馈

同一详情区显示原因、状态版本、实际使用的个人准则及来源、未使用的候选和不确定项。固定保存work级componentId，不冻结数据；即使固定证据核查，上游变更仍更新摘要并显示需重验。恢复自动选择当前适用组件。对推荐纠正单独记录为候选，不默认改长期准则。

## 持久化与接口实施边界

建议后续增加memory_entry、memory_revision、memory_use、view_intent四类持久记录，单写服务负责状态与revision；项目scope关联project/work，来源关联现有消息/decision/artifact_version。候选方法正文仍为现有skill草稿，避免第二套Skill版本。遗忘所需正文删除与最小审计策略在迁移中显式实现，不能套用不可变产物的永不删除语义。

后续新增memory.list/propose/confirm/correct/disable/forget、context.preview、viewIntent.explain/pin/unpin等命令；这是需单独发布Schema、错误码、幂等与消费者测试的建议清单，并非当前52命令已支持。先实现明确准则、作用域与手动控制，后做有结果的复盘候选，最后接模型提出ViewIntent。不先接全盘监控或任意UI生成。
