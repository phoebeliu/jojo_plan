# 测试分析设计

JP-1.0｜这是应用研发的测试计划，不是声称应用已经通过这些测试。本轮实际文档检查见审阅报告。

## 1. 分层策略

领域单元：阶段门槛、影响传播、预算、权限、幂等；数据库集成：事务、不可变版本、租约、迁移；适配契约：模型/工具/CI状态；桌面E2E：三条工作路径与中断恢复；业务样例：技能组、两种文档、系统研发；发布验证：安装、升级和可控pipeline。

默认 CI 使用 deterministic fake runtime 与假供应商，固定种子/版本，不消耗真实API。真实模型与OCR测试为单独、显式配置套件；未运行必须显示 not_run。只针对关键风险、边界与用户行为测试，不为每段提示文字做快照测试。

## 2. 环境与数据

- E1：macOS 14+ arm64、16GB，干净用户环境，有/无模型配置、有/无容器各测试。
- E2：fake runtime 支持流中断、乱序事件、错误JSON、工具调用、超额用量及进程崩溃。
- E3：本地 mock pipeline 支持幂等触发、回执丢失、状态未知和回滚；没有接触真实生产的必要。
- F1：四节点合成技能组，覆盖正确依赖、环和类型不兼容。
- F2：CI/CD经历样本及含冲突说法的参考文档；模型报告合成CSV明确标 synthetic，不冒充真实模型能力数据。
- F3：纯合成的合同/发票/回款片段，用于开发工作流、材料引用和规则产物验证；不声称实际审计合规。
- F4：非真实证件的占位图与模糊图片，用于验证项目可行性/证据不足流程，不据此测真实护照判假效果。
- F5：公开许可的小型示例Web/API项目及可控pipeline，用于研发至发布闭环；所有测试数据标明来源/许可/版本。

## 3. 用例清单

P0 为阻断发布的关键用例；P1 为首版必需功能；P2 为边界与体验。软件发布前P0/P1全部通过，P2失败需明确例外与用户接受。

| ID / 级别 | 输入或故障 | 执行与可观察预期 |
| --- | --- | --- |
| T-01 P0 | 干净Mac无开发环境 | 安装启动；可离线浏览；缺容器明确提示，不调用宿主shell |
| T-02 P0 | 正确、401、限流、无工具能力的模型服务 | 分别检查；状态准确；不把文本成功当工具能力已通过 |
| T-03 P1 | 三种职能 | 创建工作并核对模板/技能版本；类型间不串状态 |
| T-04 P1 | 混合文件含损坏PDF、重复件及超限件 | 逐项解析/拒绝；未成功件保留原因；已成功件不丢 |
| T-05 P0 | 检索失败、网页不可访问 | 来源记录保留失败；无伪造引用；研究标覆盖不足 |
| T-06 P1 | Skill正常、反例与资源缺失 | 正例输出符合契约，反例不错误触发；未验证不得启用 |
| T-07 P1 | 两类文档导出 | MD/HTML/PDF/DOCX内容与引用一致，表格/分页可读，无虚构经验或跑分 |
| T-08 P0 | 跳过PRD批准直接调用开始实现接口 | GATE_UNSATISFIED；不能靠直接IPC绕过UI |
| T-09 P0 | PRD与UX矛盾，宣讲有阻断异议 | 工程基线无法通过；处理决定回写版本后才可继续 |
| T-10 P1 | 工程产物缺ER或测试分析 | 缺项提示；不适用需有理由；空文件不算交付 |
| T-11 P0 | 植入可复现bug后开发自报修复 | 状态只到fixed；新测试证据通过才closed，失败reopened |
| T-12 P0 | 修改已批准PRD | 影响任务/测试失效，无关任务不被清空；旧成果仍可回查 |
| T-13 P0 | 旧baseline指纹批准请求 | BASELINE_STALE，不产生批准记录 |
| T-14 P0 | 综合验收缺业务证据 | insufficient；不能用软件测试通过替代业务验收 |
| T-15 P0 | 暂停/取消时正在生成或执行工具 | 立即显示pending，停止新调用，终止/核对在途操作；成果保留 |
| T-16 P0 | 文件已写但DB提交前崩溃 | 无有效版本引用缺失对象；孤立对象可回收，重启不重写用户内容 |
| T-17 P0 | DB提交后UI未收回执 | 重复requestId返回原结果；仅有一个工作/版本 |
| T-18 P0 | 两任务同时接近预算 | 原子预留，第二任务等待；总已用+预留不越过调度上限 |
| T-19 P0 | provider无用量/流中断 | 用量unknown不填0；停止新付费调用，保留核对入口 |
| T-20 P1 | 项目导出/重新导入恢复 | manifest校验通过，引用完整；密钥、受限原件默认不在包中 |
| T-21 P0 | 技能组循环/悬空依赖/不兼容输出 | 拒绝启用并定位节点；合法DAG按依赖执行 |
| T-22 P0 | 报告只有网络跑分无本次原始记录 | 明确标外部资料/未测试；不得输出“本次实测” |
| T-23 P0 | 模型/规则/数据版本变化 | 原评测标需复核；新配置不继承旧通过记录 |
| T-24 P0 | 生产候选摘要或target变更后用旧授权 | 拒绝触发，要求新的预检及授权 |
| T-25 P0 | pipeline已接受但响应丢失 | 状态uncertain→按operationId查询；绝不再次触发重复发布 |
| T-26 P0 | 外部发布成功但smoke失败 | 未交付，显示恢复/回滚；按授权策略执行且记录结果 |
| T-27 P0 | Agent伪造user审批/生产授权 | dispatcher拒绝，事件留痕，无批准状态 |
| T-28 P0 | 恶意网页/Skill要求外传密钥 | broker拒绝越权；受限内容不入日志或模型上下文 |
| T-29 P0 | 路径穿越、软链接、ZIP bomb、HTML脚本 | 拒绝越界/超限；预览不能访问Node/IPC/内部文件 |
| T-30 P0 | 抓取URL重定向到私网或metadata | 每跳拒绝；显式本地模型例外不扩大抓取权限 |
| T-31 P0 | 任务执行中撤销授权 | 后续工具失败为PERMISSION_DENIED；已发生动作仍可审计 |
| T-32 P0 | service死亡、lease过期、迟到结果 | 核对旧attempt；迟到成果不推进新基线，不双重执行 |
| T-33 P1 | 断开UI事件后重连、重复/乱序事件 | 快照游标后续重放，UI无丢失和重复状态 |
| T-34 P0 | 备份/恢复/迁移失败及磁盘满 | 原DB可恢复，失败不覆盖；旧生产授权恢复后失效 |
| T-35 P1 | 删除项目含共享技能与外部原文件 | 只删应用数据；共享引用说明；原始路径文件不变 |
| T-36 P1 | 1100×720、1440×900、200%文字 | 主任务与按钮可达，无关键内容溢出；键盘焦点正确 |
| T-37 P1 | 100项目/10,000索引记录 | 按PRD测启动/查询/保存p95，报告硬件及样本，不报空泛“很快” |
| T-38 P0 | 3次修复失败或2次无进展 | 停循环、汇总已试方案，不降低验收标准 |
| T-39 P0 | 切换先推演，假设PRD→工程设计 | 草稿链可继续；正式写代码前仍要求接受工程基线 |
| T-40 P0 | 修改他项目ID读取材料/批准基线 | 项目范围校验拒绝；不泄漏存在性之外的详细内容 |

## 4. 端到端场景

E2E-A：合成ontology技能组→正反例→修复一处依赖错误→审阅→启用→再次调用，确认锁定版本。

E2E-B：经验分享和模型报告各一份→材料矛盾/缺实测数据→按证据修订→多格式导出→渲染检查。

E2E-C：小型Web/API需求→PRD批准→UX批准→宣讲异议→工程基线→实现→植入缺陷/测试→修复→变更PRD→回归→综合验收→mock pipeline授权/回执丢失→核对→smoke→交付。

E2E-D：同一流程在PRD待审阅、工具执行中、发布意图已记录三个位置中断重启；验证不丢状态、不重复外部效果、不把provisional转approved。

## 5. 业务评测与领域验收

jojo plan 的业务验收关注团队能否产生并执行合理评测、记录证据及暴露未知。护照真假准确率和具体审计报告正确性需对应领域数据、标签、标准与人工复核；没有这些不设虚假达标数字。

模型/技能评测至少保留全部样本结果、排除样本原因、配置和失败类型。测试集与优化样例分开；报告数据覆盖、样本量及局限，禁止只挑成功案例。评测结论允许inconclusive。

## 6. 缺陷和发布标准

critical：数据泄漏/丢失、越权生产、恢复重复副作用；major：主流程不能完成、基线错配、错误宣称已测试；minor：非阻断体验；note：改进。critical/major未关闭不得正式分发；minor例外需用户签收，附影响与计划。

每份报告包含构建hash、环境、测试定义/样本版本、通过/失败/未执行、证据位置、缺陷和例外。测试“未执行”不能从统计分母消失；不以整体通过率掩盖关键用例失败。
